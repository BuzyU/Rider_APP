# RiderVoice Offline Mesh — Engineering Decisions Log

Format: `ID | Decision | Alternatives | Reason | Owner Approval | Commit`

| ID | Decision | Alternatives | Reason | Owner Approval | Commit |
|---|---|---|---|---|---|
| D-PORT | Standardize all UDP traffic (voice frames, HELLO discovery beacons, and BYE messages) on single unified port `45454` (`MeshConfig.MESH_PORT`). | Dual-port architecture separating discovery (45454) and audio (45455). | Prevents artificial port separation in single-socket link architecture, eliminates port collision risks, and simplifies packet dispatch. | APPROVED | WP-29 / WP-43 |
| D-SECRET | Offline mesh derives session keys from a 16-character Crockford Base32 pairing code via PBKDF2 with HMAC-SHA256 (`SessionKdf.deriveKeys`). For online rides, fallback requires a pre-ride shared pairing code saved in `OfflineSessionHolder.backupSession`. | Derive secret from online room name (broken, insecure); or dynamic Keystore-backed random 256-bit root with HKDF and rotation. | v1 secret model retained per OWNER_FLAGS (`KEEP_PAIRING_CODE_KEYS = true`). Room name derivation was eliminated because it was trivially guessable and insecure. Note drift from owner's 31 Oct decision (random 256-bit root + HKDF + Keystore + rotation). | PENDING-OWNER | WP-37 / WP-43 |
| D-DEBUG-FLAG | Set `OFFLINE_MESH_BUILD_ENABLED = true` in debug builds, default `false` in release builds. Feature flag local override only honoured in debug builds. | Hard disable across all builds; or enable in release unconditionally. | Enables developer iteration and automated testing on debug builds while ensuring production release builds remain fail-safe and disabled by default per OWNER_FLAGS (`ACCEPT_DEBUG_FLAG_TRUE = true`). | APPROVED | WP-42 / WP-43 |
| D-TTL | [CORRECTED 4 Nov 2026: value is 5] Default TTL is strictly 5 (`MeshConfig.DEFAULT_TTL = 5`), and `TtlPolicy.MAX_HOPS = 7` is a sanity cap only. Packets dropped if `ttl <= 0`, `hopCount > MAX_HOPS`, or `ttl + hopCount > 5`. | Larger TTL like 7 (causes broadcast storms and relay amplification). | A 6-node linear convoy requires exactly 5 hops (reaching all 6 nodes). Reconciles code and docs truth. | APPROVED | WP-41 / WP-43 |
| D-QUIET-GUARD | Enforce 400 ms quiet guard window after LiveKit audio releases capture ownership before offline mesh may acquire `AudioRecord`. | Instant takeover upon state change. | Ensures Android audio HAL and LiveKit AudioRecord threads are completely quiescent before mesh initializes, preventing HAL audio collisions. | APPROVED | WP-28 / WP-43 |
| D-STAGE4 | Stage 4 continuity client stubs (`ContinuityConfig`, `ContinuityLeaseClient`, `ContinuityModels`) retained in repository labeled "Stage 4 not built - client stubs only, no backend" until deleted in WP-50. | Build full Stage 4 backend; or delete immediately. | Stage 4 is optional & separate in the original plan; deleting in WP-50 keeps repository clean without shipping dead features. | PENDING-OWNER | WP-29 / WP-43 |
| D-FAIL-CLOSED-SECRET | Offline secret for online rides fails closed: binds `NullOfflineSecretProvider` returning `null`. Automatic fallback during online rides requires riders to type a shared pairing code in the offline lobby before the ride. | Derive secret from online room name. | Room name derivation was insecure and violated zero-trust assumptions. Fail-closed ensures offline mesh only activates with authentic authorization. | APPROVED | WP-26 / WP-37 |
| D-RESERVED-HELLO | HELLO packet fields `boundedGraphUpdates` and `transportMetadata` are labeled "Reserved - not implemented" without adding experimental wire payload bytes. | Extend wire codec with partial graph updates. | Preserves binary wire compatibility and deterministic packet layout across versions. | APPROVED | WP-27 |
| D-ROTATION-STABILITY | Do not add `android:configChanges` to `MainActivity`. Handle screen rotation via singleton session holder and argument-free Compose navigation routes. | Modify `MainActivity` manifest configuration. | Prevents altering activity lifecycle for the rest of the application. | APPROVED | WP-39 |
| D-LEGACY-NONCE | Retain wire nonce format and set `ACCEPT_LEGACY_NONCE = false` by default, constructor-injected into `ForwardingEngine`. | Change wire header format. | Prevents unauthenticated nonce malleability and replay attacks while avoiding unnecessary wire format churn. | APPROVED | WP-40 / WP-49 |
| D-HTTP-PROBE | Keep `Constants.BACKEND_URL + "/health"` as the active HTTP connectivity probe target; throttled to minimum 5s interval on `Dispatchers.IO`. | Ping public IP (8.8.8.8) or DNS lookups. | ICMP ping requires root or special sockets; HTTP health probe directly validates backend reachability without new dependencies. | APPROVED | WP-35 |
| D-MIC-RULES | Capture runs while `audioEnabled && (micToggleOn \|\| pttHeld \|\| (voxEnabled && armed))`. PTT release never closes a toggle- or VOX-opened mic. Helmet key = toggle event. | Last-event-wins or simple boolean state. | Motorcycle helmet headsets and gloved hands-free rider ergonomics require non-cancelling PTT semantics. | APPROVED | WP-36 |
| D-WARM-CAPTURE | Keep `AudioRecord` capture warm only while `micToggleOn \|\| voxEnabled`. Accept first-syllable delay for PTT-only use. | Continuously running `AudioRecord`. | Minimizes battery consumption and avoids persistent Android microphone privacy indicator in status bar. | APPROVED | WP-36 |
| D-FROZEN-FILES | Exact 0 diff against LiveKit contract files (`LiveKitManager.kt`, `RoomScreen.kt`, etc.). Zero backend changes. Zero Android permissions added. | Refactor online room code directly. | Preserves operational stability of production online ride infrastructure while keeping mesh decoupled. | APPROVED | WP-25 / WP-42 |
| D-CI-RELEASE-KEYSTORE | CI builds release APK with committed fallback keystore when `ALLOW_INSECURE_RELEASE_BUILD=true`. | Fail release assembly in CI if production secrets are missing. | Enables automated release compilation and ProGuard verification in CI without exposing production signing keys. | PENDING-OWNER | WP-42 / WP-43 |
| D-A22-ADAPTER-RECONNECT | LiveKit reconnect attempts are tracked at adapter level inside `LiveKitVoiceTransport` via rolling 60s window of `RECONNECTING` connection states, exposed as `reconnectAttempts: StateFlow<Int>` and injected into `LocalHealthSignalsProvider`. | Modify `LiveKitManager.kt` to expose reconnect counters. | Resolves defect A22 and provides real reconnect signals without modifying or unfreezing `LiveKitManager.kt` (R5). | APPROVED | WP-46 |
| D-TOKEN-REFRESH-SIGNAL | Token refresh failure signal is omitted from `LocalHealthSignals` because `ActiveRideRepository.kt` is frozen under R5 and does not expose token refresh failures. | Unfreeze `ActiveRideRepository.kt` or synthesize fake timer. | Preserves zero-diff freeze on core repository; connectivity health is reliably determined by validated internet, connection state, and HTTP health probe. | PENDING-OWNER | WP-46 |
| D-INTERFACE-FLAP-RESET | Network interface changes sampled from `ValidatedInternetSource.validatedFlow` reset the `ONLINE_RECOVERING` stability timer (`recoveryStartTimeMs = signals.lastInterfaceChangeMs`). | Ignore interface changes during recovery dwell. | Ensures flapping network interfaces cannot satisfy recovery stability, preventing premature handback to a failing online transport. | APPROVED | WP-46 |
| D-HANDOFF-BACKOFF | Failed fallback to offline mesh (`TO_OFFLINE`) enters exponential backoff (`offlineRetryMultiplier` doubling up to 8x `offlineRetryBaseMs`) with rate-limiting in a sliding window (max `maxTransitionsPerWindow` per `windowMs`). | Instant unbounded retry loop while in `FALLBACK_UNAVAILABLE`. | Prevents CPU spin, thread exhaustion, and log flooding (B3) when offline handoff fails, while permitting timely recovery when network or mesh clears. | APPROVED | WP-46 |
| D-LOCK-LIFECYCLE | Hold Android MulticastLock continuously during discovery / standby (`startDiscoveryOnly`) and release on `stop()`, while holding WifiLock only during active audio (`startAudio`/`enableAudio`/`disableAudio`). | Hold both locks continuously or hold neither in standby. | MulticastLock is necessary for the device Wi-Fi chip to receive multicast/broadcast UDP discovery frames (HELLO beacons) when screen or app is idle. However, WifiLock prevents high-performance Wi-Fi power saving and drains significant battery. Restricting WifiLock strictly to active audio sessions optimizes rider battery life while preserving peer mesh discovery. | APPROVED | WP-47 |
