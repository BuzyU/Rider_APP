| D-ENCRYPTED-BACKUP-STORE | Persist pre-ride backup pairing metadata in `EncryptedPrefsBackupSessionStore` backed by dedicated master key alias `rvmesh_backup_master_key` (isolated from `DEFAULT_MASTER_KEY_ALIAS`). If Android Keystore throws an exception, fails closed with an in-memory RAM-only backup store (never plaintext on disk) and surfaces a localized non-persistence warning in UI. | Ephemeral RAM-only backup session lost on process death; or insecure plaintext fallback. | Ensures automatic fallback survives Android background process recreation during long rides while maintaining encrypted storage, key isolation, and sign-out hygiene. | PENDING-OWNER | WP-54 / WP-63 |

| D-CRYPTO-V3 | Bump MeshPacketCodec.VERSION to 3 and derive per-source AES payload subkeys via HKDF (RFC 5869) using "rvmesh/v3/src" salt and sourceId. Wire nonce drops 3-byte sourceId hack. Relayed BYE packets are ignored for recently heard direct neighbors. Mesh is off in release builds, so bumping wire protocol version incurs zero production backward compatibility burden. | Retain v2 wire format with 3-byte sourceId prefix in nonce; or keep shared group payloadKey for all sources. | Deriving unique per-source subkeys cryptographically eliminates any possibility of (key, IV) collision across independent sender sequence spaces. Bump to version 3 cleanly rejects incompatible v2 frames with BAD_VERSION. | PENDING-OWNER | F-09 / F-10 |
| D-R5-04-SECURITY-OPTIONS | Document options for authenticated sender identity and rotation: Option A: Keep pairing-code keys with HKDF per-source subkeys (current v3 wire format; IV-safe, but any group member can forge sourceId). Option B: Random 256-bit root key stored in Keystore with HKDF subkeys + periodic key rotation + per-device ECDSA P-256 signatures for sender authentication. Option C: Option B combined with Google Nearby Connections out-of-band key exchange. | Immediate implementation without owner direction. | Cryptographic architecture changes must be decided by project owner before altering wire protocol. | PENDING-OWNER | WP-70 |
| D-R5-16-PHYSICAL-GATE | Physical multi-hop verification (PHYS-01 through PHYS-19) must be performed on at least 2-3 physical Android devices sharing a Wi-Fi hotspot with the debug peer filter before production release or enabling mesh in release builds. | Relying strictly on synthetic in-memory JVM unit tests. | Wi-Fi radio airtime contention, HAL audio transitions, and physical multi-hop packet loss cannot be proven in JVM simulation. | PENDING-OWNER | WP-70 |
| D-S-1-PHYS02-TRUTH | PHYS-02 on Wi-Fi hotspot requires MESH_SET_PEER_FILTER because Wi-Fi AP is a single collision domain. True RF multi-hop deferred to BLE/Wi-Fi Aware (Option C). | Claim physical multi-hop without peer filtering on a shared hotspot. | A shared Wi-Fi hotspot broadcasts to all connected clients; multi-hop forwarding only occurs when synthetic filtering partitions direct links. True RF multi-hop requires independent physical links. | PENDING-OWNER | WP-72 |
| D-CODEC | Adopt Opus 16 kbit/s mono 20 ms as primary speech codec with fallback to raw PCM16 if any group member lacks Opus support. Pinned pure-Java Concentus library (v1.0.2), zero native NDK dependencies, compatible across all ABIs and Android minSdk 26. Bitmask-based format negotiation via HELLO beacons with grace period and hysteresis. | Raw PCM16 only (310 kbit/s, saturates weak links); or native libopus/MediaCodec (NDK complexity or API >= 29 limit). | Reduces uncompressed voice frame from 640 B to 40 B (87.5% reduction), shrinking UDP datagram from 747 B to 69 B on v4 wire and restoring multi-speaker capacity on weak RF links. | PENDING-OWNER | WP-95 |
| D-WIRE-V4 | Adopt protocol wire format v4 featuring a compact 17-byte header (`magic1_ver_type | hop_ttl | fmt_flags | seq | session4 | src4 | prev4`), single 12-byte AEAD tag, and zero wall-clock timestamps. Sender sequence number acts as IV nonce. Replaces 75-byte v3 header and eliminates clock-skew voice packet rejection. | Retain v3 75-byte header with dual HMAC+GCM tags and wall-clock timestamps. | Shrinks header overhead from 75 B + 16 B = 91 B down to 17 B + 12 B = 29 B, eliminating 48 bytes of redundant UUIDs, 8 bytes of wall-clock time, and dual authentication overhead. Eliminates silent voice drops from clock drift. | PENDING-OWNER | WP-96 |
| D-HOP-AUTH | Per-hop authentication integrated into single 12-byte AEAD tag with `prevHop` in Associated Authenticated Data (AAD). Replaces outer 16-byte HMAC-SHA256 tag while ensuring hop-by-hop forwarding authenticity. | Retain dual-layer authentication (outer HMAC-SHA256 plus inner AES-GCM). | Outer HMAC duplicated integrity protection already provided by AES-GCM; including `prevHop` in AAD binds the immediate forwarder cryptographically with single AEAD tag, saving 16 bytes per datagram. | PENDING-OWNER | WP-96 |
| D-REPLAY | Sliding bitmask replay window (64-frame capacity) indexed by sequence number per sender short ID, replacing `DuplicatePacketCache` and string parsing. | Fixed-capacity FIFO duplicate cache with string concatenation and System.currentTimeMillis() eviction. | Zero heap allocation on packet reception, constant-time O(1) replay validation, and elimination of UUID string parsing on hot path. | PENDING-OWNER | WP-96 |
| D-RELAY-SUPPRESSION | Enable redundant relay suppression by default (`MeshConfig.SUPPRESS_REDUNDANT_RELAYS = true`). Nodes suppress retransmissions when all direct neighbors have already been heard directly by the packet source or predecessor relay. | Controlled flooding without suppression (18–25 datagrams per frame in 6-node clique). | Reduces datagrams per voice frame in a 6-node dense clique from 18–25 down to exactly 5, dropping channel airtime occupancy at 6.5 Mbit/s from 102% (channel saturation) down to 7.5%, leaving headroom for multi-party audio. | PENDING-OWNER | WP-97 |
| D-ONLINE-DTX | Online WebRTC voice recommendations: enable DTX (`dtx = true`) for `PHONE` and `WIRED` routes, tune bitrates to 24 kbit/s, lossy unaddressed PING/PONG heartbeats, and deploy SFU in Mumbai with TURN on UDP 3478 / TLS 443 to overcome Indian mobile carrier symmetric CGNAT. | Leave dtx = false and 32 kbit/s with default reliable broadcast pings. | Eliminates 50 pkt/s continuous silence transmission while mic gate is closed (97.5% idle data savings); avoids SCTP head-of-line blocking next to SOS; prevents catastrophic TCP fallback on cellular networks. | PENDING-OWNER | WP-99 |
