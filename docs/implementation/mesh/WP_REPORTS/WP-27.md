## 2. Production Call Chains

### 2.1 State Machine Lifecycle & Phase Gating (Fixes N1, V5)
- Production entry point: `App.onCreate` -> `MeshAutoSwitchManager.start()` (mobile-app/app/src/main/java/com/ridervoice/mesh/switching/MeshAutoSwitchManager.kt:93)
- Evaluates `ActiveRideRepository.state`:
  - `Phase.LIVE` with new `roomId`:
    - Calls `stateMachine.beginSession(ride.roomId, clock.nowMs())`
    - Resets all anti-flapping timers (`suspectStartTimeMs`, `recoveryStartTimeMs`, `lastSwitchTimeMs`), hysteresis windows, switch history, and backoff multipliers to 1.
    - Sets state to `AutoSwitchState.ONLINE`.
  - `Phase.LIVE` with existing `roomId`:
    - Continues 1-second evaluation loop.
  - `Phase.LOBBY` / `Phase.ENDING` / `null`:
    - Immediately calls `stateMachine.endSession()`.
    - Resets `_groupStatus.value = GroupConnectivityStatus.ONLINE_ALL`.
    - Stops evaluation ticks and disables mesh discovery/standby.
    - Never evaluates state machine transitions outside `Phase.LIVE`.

### 2.2 W-DEGRADED Rule & Offline Availability Gating
- In `SwitchingModels.kt:LocalHealthSignals`:
  - `isTotalLoss()` requires ALL of:
    1. OS network not validated or no route (`!isValidatedInternet`)
    2. Active backend `/health` probe failing (`!isHealthProbeSuccessful`)
    3. LiveKit connection disconnected (`!isLiveKitConnected`)
  - `isOnlineFailing()` requires `isTotalLoss() && offlineAvailable`.
  - High packet loss (e.g. 65%) or high round-trip time (e.g. 1500ms) alone never triggers total loss or online failing (stays in `ONLINE`).
- In `AutomaticSwitchStateMachine.evaluate()`:
  - When `offlineAvailable == false`:
    - State machine never leaves `ONLINE`.
    - Any failure emits transition diagnostic `"NO_SHARED_SECRET"` and remains in `ONLINE`.
    - Aborts any existing suspect/fallback attempt back to `ONLINE`.

### 2.3 Health Probe Throttling on Dispatchers.IO (Fixes N3)
- In `LocalHealthSignalsProvider.sampleSignals()` (mobile-app/app/src/main/java/com/ridervoice/mesh/switching/LocalHealthSignalsProvider.kt:66):
  - When `isValidatedInternet && isLkConnected`:
    - Probe is skipped entirely (0 HTTP network requests made).
    - `lastProbeResult` is set to `true`.
  - When degraded or disconnected:
    - Checked against `now - lastProbeTimeMs >= 5_000L`.
    - If inside 5000 ms, reuses cached `lastProbeResult` without network execution.
    - If elapsed >= 5000 ms, executes active probe inside `withContext(dispatcher)` (`Dispatchers.IO`), updating `lastProbeTimeMs`.

### 2.4 Group Connectivity Status Mapping (Fixes V6)
- In `SwitchingModels.kt:computeGroupConnectivity`:
  - `ONLINE_ALL`: Local device is online, all remote peers are online via LiveKit.
  - `MIXED`: Local device online with remote peers offline/ghost or on mesh; or local device on mesh with remote peers still online.
  - `OFFLINE_MESH_ONLY`: Local device on offline mesh, reachable remote peers on offline mesh.
  - `ALONE`: Remote peer list is empty or 0 reachable peers on mesh.
